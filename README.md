Claude を活用したアプリケーション開発を体系的に進めるためのプロンプトテンプレート集です。

## ファイル構成

```
personnel_ai_dlc/
├── README.md               # このファイル
└── ai_dlc_pronmpt.md       # アプリ開発用プロンプトテンプレート
```

## ai_dlc_pronmpt.md について

新規アプリケーション開発を Claude に依頼する際に使う**プロンプトテンプレート**です。  
Claude をシニアエンジニア兼プロダクトマネージャーとして動作させ、要件定義から実装まで4フェーズで開発を進めます。

### 対応プラットフォーム

- Web アプリ（バックエンド: Python）
- Android アプリ（Kotlin / Java）

### 開発フロー

```
フェーズ1  →  承認  →  フェーズ2  →  承認  →  フェーズ3  →  承認  →  フェーズ4
ユーザーストーリー     各種仕様書作成          実装計画               実装
作業計画作成
```

各フェーズは**必ず人間の承認を経てから**次に進みます。

#### フェーズ1 — ユーザーストーリー作業計画

- ステークホルダー一覧と目的の整理
- MVP スコープの確定（1人・1週間で完成できる最小限の機能）
- エピック単位の優先度付けと作業順序の決定

出力: `docs/01_user_story_plan.md`

#### フェーズ2 — ユーザーストーリー・各種仕様書

- EARS 形式によるユーザーストーリー（ID・優先度・受け入れ条件付き）
- 画面一覧と画面遷移図
- データモデル（エンティティと関係）
- 画面ごとの HTML/JS/CSS モックアップ（スタンドアロンで開けるファイル）

出力: `docs/02_user_stories.md` / `docs/02_screen_design.md` / `docs/02_data_model.md` / `docs/mock/*.html`

#### フェーズ3 — 実装計画

- 技術スタック選定と理由（Web: FastAPI / Flask / Django から選択）
- アーキテクチャ概要とディレクトリ構成案
- 1〜2時間単位のタスク分解と依存関係

出力: `docs/03_implementation_plan.md`

#### フェーズ4 — 実装

- タスク単位でコードを書き、都度報告
- 仕様が不明な箇所は実装を止めて確認
- 動作確認できる状態を常に維持

### 使い方

1. `ai_dlc_pronmpt.md` を開く
2. プロンプト本文内の `{{}}` の箇所をプロジェクト情報で埋める
3. 完成したプロンプトを Claude の会話冒頭に貼り付ける

| プレースホルダー | 記入内容の例 |
|---|---|
| `{{アプリ名}}` | タスク管理アプリ |
| `{{作りたいアプリの説明}}` | チームでタスクを共有・管理できる Web サービス |
| `{{プラットフォーム}}` | Web アプリ |
| `{{アプリ名の英名}}` | task_manager |

成果物はすべて `repo/{{アプリ名の英名}}/docs/` 以下に Markdown で保存されます。

### 設計方針

- **過剰実装しない**: MVP スコープを超える実装は提案のみ、実装しない
- **コメントは書かない**: 命名で意図を伝える
- **セキュリティ優先**: XSS・SQL インジェクション・認証不備を避ける
- **エラーハンドリングは境界のみ**: ユーザー入力・外部 API の境界だけに追加する
